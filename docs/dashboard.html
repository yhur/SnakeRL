The idea

There is one snake, the agent, with one neural network. It learns from every move it makes, using rewards from the game:

State

What the snake sees now: 32 numbers from its vision rays (the same inputs as SnakeGenetics).

Action

One of 3 moves: forward, right, left. The game's own encoding [1,0,0] [0,1,0] [0,0,1].

Reward

What the game gives back: +10 for an apple, −10 for dying, 0 for any other move.

Q-value

Q(state, action): how much reward a move will bring, now and later. The network's job is to estimate it.

The training loop, one move at a time (RLAgent/trainer.py):

for each episode (one game):
    state = new game
    until the game ends:
        action = biggest Q, or a random move with chance ε   (explore)
        next_state, reward, done = the game moves the snake
        remember (state, action, reward, next_state, done)   (replay memory)
        learn from a random batch of 64 memories             (Q-learning)
        state = next_state
    ε = ε × 0.97                                              (explore a little less)

At the start the network knows nothing and ε = 1: every move is random. The snake dies a lot, but every death teaches it a −10, and every lucky apple a +10. Slowly the Q-values become meaningful, ε shrinks, and the snake trusts its network more and more.

2 · Run state

Top right. RUNNING — Space: pause, Q: quit in green, or PAUSED — Space: one move, R: resume in orange. It reminds you which keys do what right now.

3 · Network: the Q-function

The Q-network, drawn as columns of neurons, from the state on the left to the Q-values on the right. With the default settings: 32 → 32 → 16 → 3, 1,635 weights and biases. The screenshot uses the Simple state: 11 → 32 → 16 → 3, 963 weights. It is a Keras model (build_network() in RLAgent/dqn_agent.py); the values shown are for the state the snake is in now.

Wires

Every line is one weight connecting two neurons.

  • Blue = positive weight: the signal pushes the next neuron up.
  • Red = negative weight: the signal pushes it down.
  • Thicker and brighter = stronger, compared with the strongest wire in the same layer.

Unlike in SnakeGenetics, the wires change while you watch: every training step moves the weights a little. Early on, they shift visibly from second to second.

Neurons

  • Inputs: white when 0, green when the snake sees something there. The brighter, the larger the value.
  • Hidden neurons: grey when silent, cyan when they fire (ReLU).
  • Outputs: the three Q-values. The biggest, the move the agent picks when it is not exploring, is solid green. The values themselves are in the Training panel (Q-values F / R / L).

Input labels (32)

The snake looks in 8 directions from its head: U up, UR up-right, R, DR, D, DL, L, UL. For each direction there are three inputs:

LabelMeaningValue
U-WWall in that direction1 / distance to the wall: closer means bigger
U-AApple on that ray1 if seen, else 0 (or 1/distance with Apple/Self vision = 1 / distance)
U-SIts own body (Self) on that ray1 if seen, else 0 (or 1/distance)
HU HD HL HRHead direction: up, down, left, rightexactly one of the four is 1
TU TD TL TRTail direction: which way the tail movesexactly one of the four is 1

8 directions × 3 + 4 + 4 = 32 inputs. With Snake vision = 4 directions, it is 20.

With the Simple state there are 14 inputs, each 0 or 1:

Label1 when
Wall F / R / Lmoving forward / right / left would hit the wall
Moving R / D / L / Uthe snake is heading right / down / left / up
Body F / R / Lmoving forward / right / left would hit its own body
Apple L / R / U / Dthe apple is left / right / above / below the head

In the screenshot: Moving R, Apple D and Apple R are green, and no wall or body is next to the head. (The screenshot was taken with an earlier version that had 11 inputs: one Danger F / R / L for wall or body together, and the other groups in U/D/L/R order.)

Outputs (3)

Forward, Right, Left, relative to where the snake is heading: Q(state, forward), Q(state, right), Q(state, left). The output layer has no activation function, because a Q-value can be any number, negative too.

Q-values of the next cells (while paused)

While paused, the three cells the snake can move into, forward, right and left of the head, are filled with a color for their Q-value, and the value is written in each:

  • Green: the biggest Q, the move it will make (unless it explores).
  • Yellow: in between.
  • Red: the smallest Q.

The colors are relative: they compare the three moves with each other. In the screenshot all three moves are safe, so even the "red" one is positive (2.3); it is just the worst of the three. Cells outside the board are drawn too, so you see the Q of running into the wall: a trained agent gives a deadly move a Q near −10, the death reward.

With the Simple state, the vision rays are replaced by outlines of the same three cells: red = danger (wall or body), green = safe. Those are its inputs Wall F / R / L and Body F / R / L: red when either is 1.

6 · Chart

Green: the score of every training episode. Blue: the average of the last 50 episodes. The score jumps around a lot, because one game depends on where the apples land and on random moves. The average shows real progress. The chart fills in after the first episode.

A typical run: about 100 episodes near 0 while ε is still high, then a fast climb once ε gets small (ε reaches 0.01 after about 152 episodes).

The screenshot shows what happens after that in a long run with the Simple state: the average climbs to about 21 in the first few hundred episodes, then stays flat for 5,000 more. More training does not help, because the Simple state sees danger only one cell ahead, so a long snake keeps trapping itself (see Vision vs Simple). The best score, 57, came at episode 3,700, but that was luck, not progress.

Runs vary. In test runs with the default settings, the average was about 22 apples per game at episode 300 (best 47). With Apple/Self vision = 1 / distance: about 26 (best 59). With the Simple state the snake learned much sooner: 33 apples by episode 120.

7 · Settings

The panel on the right holds every setting of a run, in five groups. Defaults are the values in RLAgent/config.py.

Apply and Defaults

  • Apply saves the settings to settings.json and uses them. Both modes start from this file, so --headless uses what you last applied here.
  • Network shape (state, vision, hidden layers, neurons, activation) decides the number and meaning of the weights. If it is unchanged, Apply asks: Keep agent (its weights, memory and ε; new settings from now on, and a new game) or New agent (untrained, ε back to the start). If it changed, the old weights no longer fit, so only New agent is possible.
  • Defaults puts every field back to its default value. Nothing changes until you press Apply.
  • When you load a checkpoint, its network shape comes with it, and all other settings stay as you set them.
  • The mouse wheel changes a field only after you click into it; over any other field it scrolls the panel.

Q-Learning

SettingDefaultMeaning
Discount γ0.9How much a reward one move later counts compared with a reward now. 0.9: a reward k moves away counts 0.9k, so the agent plans roughly 1/(1−γ) = 10 moves ahead. 0: only the next reward matters. Close to 1: far-sighted, but slower and less stable to learn.

The grey note under these settings is worked out from them:

  • “Epsilon reaches 0.01 after about 152 episodes”: 0.97152 ≈ 0.01.
  • “A reward counts about 10 moves ahead”: 1 / (1 − 0.9) = 10.
  • “Target net "off" learns against the network itself”: what happens when Target net update (below) is 0.

Q-learning in detail

What a Q-value means

Q(state, action) = the reward expected from making this move now and playing well afterwards, with later rewards discounted by γ:

Q(s, a) ≈ r1 + γ·r2 + γ2·r3 + …

With the default rewards (+10 apple, −10 death, γ = 0.9) this gives the numbers a meaning:

QRoughly means
near −10this move kills me now
near 0no apple coming soon, but safe
+6.6an apple about 5 moves away: 10 × 0.94
+10 or morean apple right now, or several soon

The Bellman target

The network's guess for Q(s, a) is improved with one real step of experience: the reward actually received, plus the discounted value of the best move from where the snake landed.

target = r + γ · maxa′ Q(s′, a′)      (just r if the game ended)
MoveTarget
an ordinary move0 + 0.9 × 4.90 = 4.41 (from the screenshot)
eats the apple10 + 0.9 × max Q(s′)
hits the wall−10 (no future after game over)

Training nudges Q(s, a) toward the target, and only for the move actually made; the other two Q-values of that state are left as they are. Rewards spread backward this way: first the move right before an apple learns it is good, then the move before that, and so on.

One training step, in code

train_on_batch() in RLAgent/dqn_agent.py, for a batch of 64 random memories:

targets = model.predict_on_batch(states)              # 1. what the network says now
next_q  = target_model.predict_on_batch(next_states)  # 2. best Q after each move
future  = gamma * next_q.max(axis=1) * (1 - dones)    # 3. Bellman: no future if done
targets[rows, actions] = rewards + future             #    only the move made changes
model.train_on_batch(states, targets)                 # 4. move predictions toward targets

ε-greedy: explore or exploit

If the agent always played its best Q, it would never find out that a move it rated low is actually good. So with chance ε it plays a random move (explore), otherwise its best Q (exploit). ε starts at 1, everything random, and shrinks after every episode: first discover, then use what was found.

Replay memory

Learning only from the move just made works badly: one move looks almost like the one before, so the network keeps over-fitting to the last few seconds and forgets older lessons. Instead every move goes into a big memory (100,000 moves), and each training step uses 64 random memories, old and new, deaths and apples mixed. Each memory is also reused many times.

Target network

The target uses Q(s′), the network's own guess. If the same network supplies the target and is trained toward it, every training step also moves the target: like chasing your own shadow. So a frozen copy, the target network, computes the targets, and it is refreshed with the latest weights every 500 moves. Set Target net update to off to see the difference.

Loss

The loss is the average (target − Q)² over a batch: how far the network's guesses are from their targets. Unlike in normal supervised learning, a falling loss is not the goal and a rising loss is not bad. The targets come from the network itself and keep changing. As the snake gets better, games get longer and Q-values bigger, so the loss usually grows: 1.69 in the screenshot, after 5,000 episodes, against about 0.1 at the start. Watch the score, not the loss.

Vision vs Simple: what the agent sees

Vision (default) · 32 inputs

The same inputs as SnakeGenetics: 8 rays, each seeing the wall, the apple and its own body; plus the head and tail direction. Close to raw perception: the network must work out for itself what is dangerous and where to go.

Simple · 14 inputs

Hand-picked yes/no facts: Wall F/R/L (would that move hit the wall?), Moving R/D/L/U, Body F/R/L (would it hit its own body?), and Apple L/R/U/D (which side of the head the apple is on). The classic DQN Snake setup, with the wall and the body as separate inputs.

With the Simple state the snake learns much sooner, because the answers to the two questions that matter are handed to it: "will this move kill me?" and "which way is the apple?". With binary Vision it sees the apple only when it lies exactly on a ray, and has to learn danger from wall distances.

But Simple sees danger only one cell ahead and knows nothing else about its body, so a long snake easily coils into a dead end it could not see coming. That is the flat chart in the screenshot: the average stays near 21 from episode ~300 to 5,272. Vision sees the body along whole rays.

A good lesson for students: the same algorithm with two different states. What the agent can see matters as much as how it learns. Switch with State (inputs), then Apply → New agent, and compare the charts.

Reinforcement learning vs the genetic algorithm

SnakeGenetics trains the same kind of network on the same inputs, in a completely different way:

SnakeGenetics (GA)SnakeRL (DQN)
Snakes500 per generation, each its own brainone agent, one network
Feedbackone fitness number per gamea reward after every move
How weights changeselection, crossover, mutation: no gradientsgradient descent toward Bellman targets
Outputs meanjust "which move": the biggest winsQ-values: expected future reward of each move
Randomnessin breeding (mutation)in playing (ε-greedy exploration)
Memorynone: good genomes survivereplay memory of past moves

Modes & files

Dashboard: python main.py

Watch it learn move by move, pause and step. A few hundred moves per second at Max.

Headless: python main.py --headless

No window, as fast as possible. 8 games at once share one agent and one replay memory (see below). One line per episode. Ctrl+C stops it and saves.

python main.py --headless -e 300              # stop after 300 episodes
python main.py --headless --games 1           # one game at a time, like the dashboard
python main.py --load saves/checkpoint_vision.npz    # continue in either mode
python main.py --config my_settings.json      # use another settings file
FileWhat it holds
settings.jsonThe settings last applied in the dashboard. Both modes start from it.
saves/*.npzCheckpoints: settings, network weights, ε, counters, history. Headless saves saves/checkpoint_<vision|simple>.npz every 50 episodes and when it stops. The replay memory is not saved; it refills quickly.

A good workflow: train with --headless, then Load... the checkpoint in the dashboard, untick Learning, and watch the trained snake play.

Several games at once (headless)

Asking the network about 8 states in one call costs about the same as asking about 1. So headless mode plays 8 games side by side (--games), all sharing one agent and one replay memory. Each round:

one network call picks a move for all 8 games     (agent.choose_actions)
each game makes its move; all 8 are remembered
one training step on a batch of 64 × 8 = 512      (agent.learn(moves=8))

The network learns from as many memories per move as with one game, but in one big training step per round instead of 8 small ones. The dashboard always plays one game, so it stays easy to follow.
